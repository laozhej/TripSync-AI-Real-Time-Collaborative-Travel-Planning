## Initial shared board — 2026-10-30

Implemented initial WebSocket snapshot, pin, volatile `trip.command.ack`, board fan-out and later committed watermark, plus a shared HTTP pin service. A failed batch freezes the affected room; a newly instantiated room manager reloads committed items and advances its epoch. Joining flushes pending board writes before the membership transaction while holding the room actor lock. This is ordered in two transactions rather than the single combined transaction described by the planned architecture.

With the disposable PostgreSQL database, `$env:PYTHONPATH='backend'; $env:TEST_DATABASE_URL=<local disposable URL>; .\.venv\Scripts\python.exe -m pytest backend\tests -q` returned **23 passed**. The integration flow includes two authenticated sockets receiving the same pin, a volatile acknowledgement and committed watermark, Viewer denial over HTTP and socket, persisted reload with a new epoch, and logout closing a socket. A unit test injects a batch failure and checks that the room freezes. This is not a complete role matrix, outage recovery drill or performance test. A logout integration check initially failed because the returned response had no explicit status; setting 204 fixed it.

With Uvicorn and Vite started locally, `$env:PYTHONPATH='backend'; .\.venv\Scripts\python.exe backend\tests\browser_phase1.py` returned `Two browser sessions: create, join, identical pin, commit watermark succeeded`. It used two separate headless Chrome contexts and cleaned its own generated database records. The first browser attempt failed because the WebSocket runtime library was absent; installing `websockets` and restarting Uvicorn resolved it. `npm run build` succeeded after the client changes. No latency target is claimed.

Known gaps: the snapshot is a minimal item/sequence snapshot rather than the complete planned budget/member/chat schema; browser reconnect and refresh are not automatic; persistence freeze requires process restart; no full clean-install evidence, full four-role matrix, invite lifecycle UI, admin CLI, complete dataset exception support, or concurrency/outage drills have been completed. All phase 1 backlog checkboxes remain unchecked pending their complete acceptance criteria.

## Phase 1 acceptance run — 2026-10-30

The first-slice backlog criteria for TASK-001–007 were checked against their implemented scope. The test setup used Windows 11 Home Single Language on an Intel Core i7-10875H, Python 3.13.1, PostgreSQL 18.1, Node 24.13.0, npm 9.9.4 and Chrome 156.0.8078.79. All clients and services ran on the same machine using loopback; the dataset was the checked-in synthetic Lisbon fixture. No model was used.

- A fresh temporary Python virtual environment installed `backend/requirements.lock`. `backend/tests/clean_setup.py` created a randomly named disposable PostgreSQL database, applied revisions through `0008_venue_search`, imported the dataset and ran the backend suite: **26 passed, 1 warning in 15.74 seconds**. It then removed only the database it had created. One warning concerns Starlette's deprecated httpx TestClient integration; pytest-asyncio also emitted a fixture-scope deprecation notice.
- `npm ci` installed the locked frontend dependencies and reported zero audit vulnerabilities; `npm run build` succeeded. The browser test started one Uvicorn worker and Vite, then used two isolated headless Chrome contexts to register, create/join a room, observe the same pin, observe the committed watermark, reconnect, and create/revoke an invitation. Both processes were stopped after testing.
- One join-to-snapshot sample, measured from the Join button until the snapshot rendered, was **134.9 ms**. This includes local join, catalog and socket setup. It is a single observation, not a latency distribution, load test, or proof that performance targets hold generally.
- The backend tests cover Planner and Leader pin actions through HTTP and socket, Viewer and Admin-without-membership rejection, an Admin who is a Viewer, expired JWTs including a socket that expires while open, logout socket closure, removed membership, foreign-dataset venue rejection, refresh rotation/reuse, concurrent redemption for the last room place, valid Viewer invitation, expiry/revocation and capacity rejection. These are first-slice cases; phase 4's full security matrix and adversarial assessment remain required.
- Batch persistence is tested with a rejected transaction that rolls back pending pins, followed by a membership join that commits those pins and the join together. A forced failure freezes the room; reinitializing the room manager restores committed state with a new epoch and a stable planning-session ID. A generated PostgreSQL tsvector and GIN index are present and tested. No database row-lock statement is used.

Failures encountered and corrected included an incorrect shell working directory, missing Windows timezone data, the missing Uvicorn WebSocket dependency, an incorrect logout status, a socket-close race, and a second attempt to start servers on occupied ports. A targeted source-pattern scan returned only known test fixture files; it is not a full history secret audit. The user's exposed local credentials were rotated and `.env` is Git-ignored. No secret values are recorded here.

Phase 1 completion applies to the documented first slice. Later features remain required: full board lifecycle and CAS, presence/moderation, chat, complete snapshots for those features, constraint matching and real-model RAG, voting, weighted budgets, recommendations, analytics, Admin upload, recovery drills and full performance/security evidence. Browser automatic HTTP refresh is implemented but its real expiry/failure path has not been separately exercised; refresh-token rotation and reuse are covered by database integration tests.
