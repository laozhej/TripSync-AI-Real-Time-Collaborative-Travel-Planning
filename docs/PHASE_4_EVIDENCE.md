## Load and target outcomes

Ten native sockets represent five distinct identities in two rooms (three/two identities, five sockets each). Room capacity was configured to 50, not proven at 50. Two-room operations are interleaved; 1,000 moves and 1,000 HTTP reads are sequential command/read pairs with 25-ms pacing. This is not a saturated concurrent-request benchmark. Warmup was 20 moves over 1.32 seconds, shorter than the proposed two minutes. Background local restore/dependency/Chrome verification overlapped parts of the run; no recommendation training ran during measured load.

Twenty same-version races produced exactly one accepted next version and one explicit stale conflict per pair. Twenty distinct-overlap cases notified and resolved; all active item values agreed across the clients and authoritative snapshots, including reconnect budgets. HTTP status failures: zero. Expected stale-version rejections are recorded separately from availability failures. Raw samples are `evidence/performance/samples.json`; per-route/clock/client details are in summary.json and target-results.json. Nearest-rank empirical quantiles include all successful HTTP reads. ## Actual model performance and failures

The first full suite failed live inference because Ollama was stopped. The first load attempt completed collaboration checks then aborted on the unavailable model service; no model success is claimed for it. Starting/preloading the local runtime restored service. A retained unpreloaded profile (`unpreloaded-*.json`) returned 101 labeled fallbacks; its retries are explicitly reclassified as unpreloaded retries, not warm samples.

The next completed baseline (`summary.json` / samples.json AI entries) included one cold and 100 preloaded requests, all of which still fell back. A synthetic diagnostic using a separate 60-second diagnostic deadline completed the old 53-token output in 10.19 s (2.71 s prompt evaluation, 7.33 s token evaluation). That diagnostic never changed the application timeout. Compact selection removes redundant IDs/status/reason fields and duplicated schema prose; descriptions shrink to 300 characters and repetitive already-validated hours stay out of the model prompt. A 10-token response then took 2.05 s in the direct diagnostic. All filters and source validation remain in Python; model free prose is never shown.

Post-optimization command: same disposable wrapper/ports with `backend/tests/phase4_ai_measure.py`. It explicitly unloads the model, makes one cold application request, completes a disclosed 4.14-second preload, then issues 100 unique warm requests. Raw results are ai-samples.json and ai-summary.json. **99/100 warm responses are actual grounded model answers**, P50 1,472 ms, P95 1,600 ms, maximum 2,422 ms. One warm fallback took 2,544 ms; all-response warm P95 is also 1,600 ms. The cold request returned a labeled fallback in 2,642 ms, so cold real-generation availability is not accepted. No HTTP failures occurred. One browser model request/preload overlapped this profile and also fell back; this run therefore includes contention and is not an exclusive single-request model benchmark. The failed browser run is retained as a failure in this report and rerun independently for the final walkthrough.

The <3-s warm **HTTP** P95 meets the measured target, with a disclosed 1% fallback rate. It does not establish browser-rendered P95 or diverse-query/cold inference reliability. The repeated synthetic question encourages prefix caching; no claim is made about a broader question distribution. Never count the two diagnostic 60-second-deadline responses or deterministic fallbacks as application model successes.

## Restore, contracts, and submission

`test_phase4_restore.py` runs real pg_dump/pg_restore with an ignored temporary archive and child-environment credentials. The source is asserted disposable, the restored DB is newly generated, and finally removes both the archive and restore database. Every public table's sorted logical-row count/digest matches exactly before hydration (`evidence/operations/restore.json`). Startup then produces a new epoch, resolves the saved overdue election once, applies the correct locked winner, restores the independent INR split, and leaves the sequence unchanged on a repeated tick. Existing lost-commit-ack integration separately proves commit-then-acknowledgement-loss recovery and deduplication. Raw database contents/password hashes/tokens are excluded from evidence.

Actual extracted columns/indexes and OpenAPI are in evidence/contracts; README/setup/API/socket/architecture docs now distinguish implemented routes from former proposed aliases. No migration, extra backend, currency rewrite or worker increase was introduced. `http/tripsync.http` is a local shareable collection with private-variable placeholders. `scripts/scan-submission.py` checks current Git-visible files and every reachable history blob for configured long secret values and private-key/AWS/GitHub/JWT signatures; its report discloses detection limits. The scan is not a proof that every possible old/rotated credential is absent. `scripts/package-submission.py` writes a source/evidence manifest and ignored ZIP, excluding Git internals, ignored runtime/dumps/credentials, and its self-referential manifest digest. Incremental source commits remain in this repository. See RETROSPECTIVE.md and DEMO_AND_SUBMISSION.md for the final packing list and limitations.
